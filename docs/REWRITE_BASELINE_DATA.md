# Rewrite baseline: persisted data shapes

This records the data boundaries before the staged rewrite. The JSON files in `tests/fixtures/rewrite-baseline/` are synthetic examples based on the current writers and readers, not a user's private export. They contain the fields that migration must preserve; they are not exhaustive settings backups or full SillyTavern chat files.

| Boundary | Current shape and owner | Writer / reader |
| --- | --- | --- |
| Settings backup | Raw `extension_settings.sillynpc` object. `exportSettingsData()` writes it as JSON; import requires a `characters` array, merges the object, then runs `normalizeSettings()`. Root keys include `version`, `characters`, `personaData`, `master_items`, `activeSystem`, `profileHints`, and `statusTracker`. | `src/core/settings.js`, `src/core/settings-defaults.js`, `src/core/settings-migration.js` |
| Chat metadata | SillyTavern's `context.chatMetadata`: `sillynpc_npcs` chat-owned cards; `sillynpc_cast` category/include/exclude selector; `sillynpc_system` name; `sillynpc_persona` avatar filename; `sillynpc_status_state`; `sillynpc_status_history`; `sillynpc_swipe_base`; `sillynpc_faces` run assignments. Keys are optional in older chats. | `src/characters/character-repository.js`, `src/characters/characters.js`, `src/tracker/status-chat-session.js`, `src/tracker/status-state-storage.js`, `src/characters/default-portraits.js` |
| NPC card | `id`, `name`, `imageUrl`, `images`, `color`, `category`, `imageFit`, `aliases`, `lorebook: {world, uid} | null`, `autoLinkLorebook`, `statusOverrides`, `statusCollections`, `profile`. A card is stored in chat metadata when a chat is open, otherwise in settings `characters`. The `lorebook` pointer names an entry in SillyTavern world info. | `src/characters/characters.js`, `src/characters/character-repository.js` |
| Tracker state | `global` stat map; `characters` array of named NPC stats and collections; active `player` with `name`, `personaKey`, stats and collections; optional `players` map for other personas; `recently_deleted`; `timestamp`; and standing item decisions. Player stat values are strings, including `XP: "3/10"` remainder/cap and `Level: "2"`. The reader reports an absolute XP total, which progression rolls into these stored values. | `src/tracker/status-status-summary.js`, `src/tracker/status-state-storage.js`, `src/tracker/status-persona-state.js`, `src/tracker/progression.js` |
| Persona master | Settings `personaData` is keyed by persona avatar filename. The record can carry player card identity, profile, portrait, lore link, stats, and collections. Chat state has its own current player values and may seed them from this master. | `src/tracker/status-persona-state.js` |
| Character transfer | `{format: "sillynpc-characters", version: 2, exported, characters: [...]}`. Each record contains name, color, category, imageFit, aliases, nonempty fixed profile fields, `innateStats`, and optional portable lore `{keys, content}`. Version 2 omits local portrait paths and lorebook pointers; older transfer files may still contain portraits. This is distinct from a whole-settings backup. | `src/characters/character-transfer.js` |
| System export | A bare saved preset object: `{version: "2.1.0", metadata: {name, description, author}, config, world}`. Current `config` carries copied root settings and a nested `statusTracker` configuration. Current `world` carries `characters`, `personaData`, and `master_items`. Older presets may have flat tracker configuration or no `world`. | `src/tracker/status-system-presets.js`, `src/tracker/status-checkpoints.js`, `src/ui/system/ui-system-manager.js` |
| Per-message records | `message.extra` may hold `sillynpc_pending`, `sillynpc_review_notes`, `sillynpc_review_refused`, `sillynpc_applied`, `sillynpc_applied_swipe`, `sillynpc_threads`, `sillynpc_globals`, `sillynpc_chars`, `sillynpc_status_raw`, `sillynpc_edits`, and `sillynpc_reader_report`. These are separate from chat metadata and can travel with swipes. | `src/tracker/status-review.js`, `src/tracker/snapshots/`, `src/tracker/status-history.js`, `src/tracker/extractor/status-extraction-report.js` |

The `old-chat.json` fixture covers chat state, player XP and level, history, and the latest-swipe base. The chat-owned NPC fixture has a live lorebook link to `lorebook-entry.json`; the character transfer fixture carries the linked entry's text instead. The System fixture deliberately includes the legacy `world` payload so future migration tests can confirm those values survive separation from reusable rules.

These fixtures load as JSON and have basic boundary assertions in `tests/rewrite-baseline-fixtures.mjs`. A running SillyTavern smoke pass remains necessary to record current host behavior; JSON fixtures cannot verify rendering or events.

## System migration outcome

The original Phase 2 migration archived an old preset's embedded `world` under `settings.systemWorldArchive`. On 2026-09-29 the user authorized dropping saved world data during cleanup. Loading settings now clears that archive; importing an old System keeps its rules but discards its embedded characters, persona records, and item library. New System exports contain only a normalized `schemaVersion: 1` definition; local saved presets still carry `config` for the System Builder and tracker.
